**Goal:** 把前端契约 pin 到 jimu v0.4.0（`df33b82a740930cacaaa03676e76b99d699188ce`），接通会话引导（`GET /auth/me`）与注册（`GET /auth/config` + `POST /auth/register`），并交付第一个权限驱动的真实管理页 `/platform/tenants`。

**Tech Stack:** Vue 3.5、TypeScript 5.9、Vite 8、vue-router 5、TanStack Vue Query 5、Element Plus 2.14、openapi-fetch 0.17、Vitest 5、Playwright 1.63。

## Review Focus

以下六类输入/条件最容易让使用者踩坑，全部在对应 task 里有测试钉住：

1. **`status` 筛选的两种极端**：不筛选必须**完全省略** `status` 参数（显式 `?status=` 会被 gin 绑成 `0`＝只查停用）；而 `status=0`（只看停用）必须**保留**。→ Task 4 `tenant-params.spec.ts`。
2. **载荷型端点的响应形状**：`/auth/login`、`/auth/me`、`/auth/config`、`/auth/register` 的生成类型是「载荷」，运行时却是标准信封 `{code,message,data,request_id}`。直接当裸载荷读会静默拿到 `undefined`。→ Task 1 `api-unwrap.spec.ts` + Task 2 `identity.spec.ts`。
3. **空 `data` 的成功响应**：`PUT/DELETE /tenants/{id}`、`PUT /tenants/{id}/plan` 返回 `{"code":0,"message":"ok"}`（`omitempty` 省略了 `data`）。用旧 `unwrap` 会把成功判成失败。→ Task 1 `api-unwrap.spec.ts`（`unwrapOk`）+ Task 4 `tenants-api.spec.ts`。
4. **`KeyMatch` 的语义与方向**：不是按 `/` 分段匹配，`keyMatch(请求路径, 已授权 resource)` 是「key2 首个 `*` 之前的前缀相等」；参数交换或分段实现会让「后端允许、前端拒绝」。→ Task 2 `permission.spec.ts`。
5. **引导失败与会话失效必须区分**：`/auth/me` 的 500/网络错误**不能**登出（否则后端一抖动就把用户踢出）；401/404 必须清会话并跳登录。零角色用户是 `200 + 空数组`，**不是**会话失效。→ Task 2 `identity.spec.ts` + `session-guard.spec.ts`，Task 4 的 E2E。
6. **权限点要用「具体请求路径」判定**：后端种子权限是 `/api/v1/tenants` GET/POST 与 `/api/v1/tenants/*` GET/PUT/DELETE；行内操作必须传 `/api/v1/tenants/7` 这类真实路径，传 `/api/v1/tenants` 会因前缀语义判成无权限。→ Task 4 `tenants-view.spec.ts`。

#### 为什么需要 `unwrapPayload` 与 `unwrapOk`

- `openapi-fetch` 的 `data` 类型来自生成的响应 schema。后端 swag 注解对五个「载荷型」端点只标了载荷，`openapi-typescript` 生成的类型因此**不含信封字段**。`unwrap(body: Envelope | undefined)` 的形参是全可选属性的「弱类型」，把载荷类型传进去会触发 TS weak-type 报错（无属性重叠）；即使绕过编译，运行时读到的仍是信封里的 `code`/`data`。
- `response.OK(c, nil)` 的 `Body.Data` 带 `json:"data,omitempty"`，实测序列化为 `{"code":0,"message":"ok"}`——**`data` 键不存在**。`unwrap` 对缺 `data` 的 `code === 0` 响应会抛「响应缺少 data 字段」，把成功判成失败。

```ts
/**
 * 解出「载荷型」端点的 data。
 *
 * 后端 swag 注解对这五个端点（/auth/login、/auth/refresh、/auth/me、/auth/config、
 * /auth/register）只标了载荷，生成的响应类型因此不含信封字段；运行时后端仍然返回
 * `{code, message, data, request_id}`。直接用 unwrap 会触发 TS 弱类型报错，
 * 这里显式接纳 `unknown`，形状校验仍然只有 unwrap 一份。
 */
export function unwrapPayload<T>(body: unknown): T {
  return unwrap<T>(body as Envelope | undefined)
}

/**
 * 只确认「操作成功」，不要求响应带 data。
 *
 * `response.OK(c, nil)` 的 Body.Data 是 `json:"data,omitempty"`，实测序列化为
 * `{"code":0,"message":"ok"}`——没有 data 键。PUT /tenants/{id}、DELETE /tenants/{id}、
 * PUT /tenants/{id}/plan 都是这一类，用 unwrap 会把成功判成「响应缺少 data 字段」。
 */
export function unwrapOk(body: unknown): void {
  const envelope = body as Envelope | undefined
  if (envelope === undefined) {
    throw new ApiError(ErrorCode.unknown, '服务端返回了空响应')
  }
  if (envelope.code !== ErrorCode.ok) {
    throw new ApiError(
      envelope.code ?? ErrorCode.unknown,
      envelope.message ?? '请求失败',
      envelope.request_id,
    )
  }
}
```

```bash
#!/usr/bin/env bash
# 契约 pin 校验：证明 contracts/jimu.swagger.yaml 确实来自 backend-commit.txt 记录的提交。
#
# 属性：只读、零凭据、fail-closed。两个仓都是公开仓库，因此 git fetch 不需要任何 token；
# pin 一个未推送的提交会直接 fetch 失败 ⇒ 变红。这正是「契约只能来自已推送提交」的强制手段。
#
# 用法：
#   scripts/check_contract_pin.sh              # 校验 backend-commit.txt 记录的 SHA
#   scripts/check_contract_pin.sh <sha>        # 校验指定 SHA（本地观察失败用）
set -euo pipefail

repo_root=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
remote="${JIMU_REMOTE:-https://github.com/wangkuntian/jimu.git}"
swagger_path="docs/openapi/swagger.yaml"
pin_file="$repo_root/contracts/backend-commit.txt"
swagger_file="$repo_root/contracts/jimu.swagger.yaml"

sha="${1:-$(tr -d '[:space:]' < "$pin_file")}"
if [[ ! "$sha" =~ ^[0-9a-f]{40}$ ]]; then
  echo "::error::pin 必须是 40 位小写 hex SHA，实际是：$sha"
  exit 1
fi
[ -s "$swagger_file" ] || {
  echo "::error::缺少契约副本：$swagger_file"
  exit 1
}

tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT
git -C "$tmp" init -q
if ! git -C "$tmp" fetch --depth=1 "$remote" "$sha"; then
  echo "::error::无法从 $remote 取到 $sha——pin 必须是已推送的提交"
  exit 1
fi
git -C "$tmp" show "FETCH_HEAD:$swagger_path" > "$tmp/pinned.yaml"

if ! diff -u "$tmp/pinned.yaml" "$swagger_file"; then
  echo "::error::contracts/jimu.swagger.yaml 与 $sha 的 $swagger_path 不一致，请运行 scripts/sync-contract.sh <ref> 后重新生成类型"
  exit 1
fi
echo "✅ 契约副本与后端提交 $sha 的 $swagger_path 逐字节一致"
```

```bash
#!/usr/bin/env bash
# 契约同步：把 jimu 某个提交的 docs/openapi/swagger.yaml 固定到本仓，再重新生成类型。
#
# 用法：
#   scripts/sync-contract.sh                  # 默认取本地 ../jimu 的 HEAD（提交态，不是工作区）
#   scripts/sync-contract.sh <sha|tag|branch> # 从公开远端 fetch --depth=1 后取该提交
#
# 取「提交态」而不是工作区文件：后端仓库里未提交的本地改动不应该悄悄进契约副本。
# CI 会用同一个 SHA 去公开仓取证并逐字节比对，所以 pin 必须是**已推送**的提交。
set -euo pipefail

repo_root=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
backend_dir="${JIMU_BACKEND_DIR:-$repo_root/../jimu}"
remote="${JIMU_REMOTE:-https://github.com/wangkuntian/jimu.git}"
swagger_path="docs/openapi/swagger.yaml"

if [ "$#" -gt 1 ]; then
  echo "用法: scripts/sync-contract.sh [<sha|tag|branch>]" >&2
  exit 2
fi

tmp=""
cleanup() { [ -n "$tmp" ] && rm -rf "$tmp"; }
trap cleanup EXIT

if [ "$#" -eq 0 ]; then
  [ -d "$backend_dir/.git" ] || {
    echo "❌ 找不到本地后端仓库：$backend_dir（可用 JIMU_BACKEND_DIR 覆盖，或传入 <sha|tag> 走远端）" >&2
    exit 1
  }
  sha=$(git -C "$backend_dir" rev-parse HEAD)
  source_repo="$backend_dir"
  if ! diff -q <(git -C "$backend_dir" show "$sha:$swagger_path") "$backend_dir/$swagger_path" > /dev/null; then
    echo "❌ $backend_dir 的 $swagger_path 有未提交改动，拒绝把工作区内容写进契约副本" >&2
    exit 1
  fi
else
  tmp=$(mktemp -d)
  git -C "$tmp" init -q
  git -C "$tmp" fetch --depth=1 "$remote" "$1"
  sha=$(git -C "$tmp" rev-parse FETCH_HEAD)
  source_repo="$tmp"
fi

git -C "$source_repo" show "$sha:$swagger_path" > "$repo_root/contracts/jimu.swagger.yaml"
grep -q '^swagger:' "$repo_root/contracts/jimu.swagger.yaml" || {
  echo "❌ $sha 的 $swagger_path 不是 Swagger 文档，拒绝写入" >&2
  exit 1
}
printf '%s\n' "$sha" > "$repo_root/contracts/backend-commit.txt"

echo "✅ 已固定 jimu@$sha"
( cd "$repo_root" && pnpm run api:types )
```

1. `keyMatch` 复刻 casbin v3 `util.KeyMatch`：`star = grantedResource.indexOf('*')`；无 `*` → `requestPath === grantedResource`；有 `*` 且 `requestPath.length > star` → `requestPath.slice(0, star) === grantedResource.slice(0, star)`；否则 `requestPath === grantedResource.slice(0, star)`。**方向不能交换**：请求路径是 key1，授权 resource 是 key2。权限点 resource 全是 ASCII 路径，JS 的 UTF-16 `length`/`slice` 与 Go 的字节下标等价。
2. `hasPermission` = 「存在一个权限点，`keyMatch(请求路径, p.resource)` 且 `p.action === action || p.action === '*'`」；身份未加载时返回 `false`（fail-closed）。

4. `ensureIdentity()` 单飞；**只在成功时缓存**（身份已在内存时直接返回 `'ok'` 不发请求）；失败后可重试。
5. `ensureIdentity()` 自己**不导航、不清会话**：401/404 只清身份并返回 `'unauthenticated'`，由守卫决定跳登录（避免与 `onSessionExpired` 订阅抢导航）；500/网络/形状异常返回 `'unavailable'`，会话与身份都不动。

```ts
import { getIdentity } from './session'

/**
 * Casbin v3 `util.KeyMatch` 的前端等价实现。
 *
 * 后端 matcher 是 `keyMatch(r.obj, p.obj) && (r.act == p.act || p.act == "*")`，
 * 即 `keyMatch(请求路径, 已授权 resource)`。语义是「key2 中第一个 * 之前的字符串前缀相等」，
 * **不是**按 `/` 分段匹配：`('/api/v1/users', '/api/v1/user*')` 在后端为 true。
 * 参数顺序不能交换，否则 `('/api/v1/tenants/*', '/api/v1/tenants')` 会退化成精确比较。
 */
export function keyMatch(requestPath: string, grantedResource: string): boolean {
  const star = grantedResource.indexOf('*')
  if (star === -1) {
    return requestPath === grantedResource
  }
  if (requestPath.length > star) {
    return requestPath.slice(0, star) === grantedResource.slice(0, star)
  }
  return requestPath === grantedResource.slice(0, star)
}

/** 身份未加载时一律 false：判定必须 fail-closed。 */
export function hasPermission(requestPath: string, action: string): boolean {
  const current = getIdentity()
  if (current === null) {
    return false
  }
  return current.permissions.some(
    (point) => keyMatch(requestPath, point.resource) && (point.action === action || point.action === '*'),
  )
}
```

```ts
import { api } from '../api/client'
import type { Identity } from '../api/types'
import { unwrapPayload } from '../api/unwrap'
import { clearIdentity, getIdentity, saveIdentity } from './session'

export type IdentityStatus = 'ok' | 'unauthenticated' | 'unavailable'

/** 进行中的引导；并发导航共享同一请求，成功后再调用直接命中缓存。 */
let inflight: Promise<IdentityStatus> | null = null

/**
 * 加载当前会话身份。
 *
 * - 成功缓存：身份已在内存时直接返回 `'ok'`，不再发请求。
 * - 失败不缓存：后端抖动后下一次导航会重试。
 * - 本函数不做任何导航、不清理 token：401/404 只把身份清空并返回 `'unauthenticated'`，
 *   是否跳登录由路由守卫决定，避免与 onSessionExpired 订阅抢导航；
 *   500/网络错误返回 `'unavailable'`，会话保持有效（后端抖动不能把用户踢出）。
 */
export function ensureIdentity(): Promise<IdentityStatus> {
  if (getIdentity() !== null) {
    return Promise.resolve('ok')
  }
  inflight ??= loadIdentity().finally(() => {
    inflight = null
  })
  return inflight
}

async function loadIdentity(): Promise<IdentityStatus> {
  let status: number
  let body: unknown

  try {
    const result = await api.GET('/auth/me')
    status = result.response.status
    body = result.data
  } catch {
    // 网络错误不清理会话：可能只是离线。
    return 'unavailable'
  }

  if (status === 401 || status === 404) {
    // 404 是「token 有效但账号已删」（业务码 2001），与 401 同样按会话失效处理。
    clearIdentity()
    return 'unauthenticated'
  }
  if (status < 200 || status >= 300) {
    return 'unavailable'
  }

  let identity: Identity
  try {
    identity = unwrapPayload<Identity>(body)
  } catch {
    return 'unavailable'
  }

  if (!isIdentity(identity)) {
    clearIdentity()
    return 'unavailable'
  }

  saveIdentity(identity)
  return 'ok'
}

/** roles/permissions 必须是数组：`null` 会让权限判定在渲染期直接抛错。 */
function isIdentity(value: Identity): boolean {
  return (
    Array.isArray(value.roles) &&
    Array.isArray(value.permissions) &&
    typeof value.user === 'object' &&
    value.user !== null
  )
}
```

```ts
export async function resolveGuardNavigation(to: GuardTarget): Promise<SessionNavigation> {
  // 冷启动（sessionStorage 里有 refresh token）与登录后都走这里：受保护路由先取身份，
  // 页面渲染时 hasPermission 就已经有数据。失败不拦：'unavailable' 只是后端抖动。
  if (hasSession()) {
    const status = await ensureIdentity()
    if (status === 'unauthenticated') {
      // 守卫自己会导航，所以用 clearSession 而不是 expireSession，避免订阅二次跳转。
      clearSession()
    }
  }

  return resolveSessionNavigation(to)
}
```

```ts
export interface RegisterPayload {
  username: string
  password: string
  tenant_name?: string
  tenant_code?: string
  captcha_id?: string
  captcha_code?: string
}

/** 注册相关开关；公开端点，关闭公开注册时依然存在并返回 false。 */
export async function fetchAuthConfig(): Promise<AuthConfig> {
  const { data } = await api.GET('/auth/config')
  return unwrapPayload<AuthConfig>(data)
}

export async function register(payload: RegisterPayload): Promise<RegisterResult> {
  const { data, response } = await api.POST('/auth/register', { body: payload })

  // 注册限流走 HTTP 429，响应体可能不是标准信封，先按状态归一化错误码。
  if (response.status === 429) {
    throw new ApiError(ErrorCode.rateLimited, '注册请求过于频繁，请稍后再试')
  }

  return unwrapPayload<RegisterResult>(data)
}
```

**关键取值与规则**

- `sort` 白名单 `id` / `code` / `created_at`；`order` 只允许 `asc` / `desc`（后端对未知排序字段返回 400）。
- `keyword` 对 `code` 与 `name` 子串匹配，前端**传原文**（后端已转义 `%` `_` `!`）；空/仅空白时**省略**。
- `status`：`''` 表示不过滤 → **必须完全不传**；`0` 是合法筛选值 → **必须保留**。
- 权限点：列表/新建用 `apiResource('/tenants')` + `GET`/`POST`；行内操作用 `apiResource(`/tenants/${id}`)` + `GET`/`PUT`/`DELETE`；分配套餐用 `apiResource(`/tenants/${id}/plan`)` + `PUT`；套餐名用 `apiResource('/tenant-plans')` + `GET`（为 `false` 时不请求套餐）。
- `plan_id === 0` → 「未分配」；`plan_id` 在套餐列表里找不到 → `#<id>`。
- 四态：加载中 / 空（一句说明 + 主操作「新建租户」）/ 错误（可重试 + `request_id`）/ 无权限（`1003`，**不跳登录**）。

```ts
export type TenantSort = 'id' | 'code' | 'created_at'
export type TenantOrder = 'asc' | 'desc'
/** `''` 表示「不筛选」；`0`/`1` 是真实的筛选值（0=停用、1=启用）。 */
export type TenantStatusFilter = '' | 0 | 1

export interface TenantFilters {
  page: number
  pageSize: number
  sort: TenantSort
  order: TenantOrder
  keyword: string
  status: TenantStatusFilter
}

export interface TenantListQuery {
  page: number
  page_size: number
  sort: TenantSort
  order: TenantOrder
  keyword?: string
  status?: number
}

/**
 * 构造 /tenants 的查询参数。
 *
 * 两条必须守住的语义：
 * - 不筛选状态时必须**省略** status —— 显式写成 `?status=`（空串）会被 gin 按整数绑成 0，变成「只查停用」；
 * - `status: 0` 是合法筛选值，必须保留。
 * keyword 传原文（后端已对 `%`/`_`/`!` 转义并配 ESCAPE），空串省略。
 */
export function buildTenantListQuery(filters: TenantFilters): TenantListQuery {
  const keyword = filters.keyword.trim()
  const query: TenantListQuery = {
    page: filters.page,
    page_size: filters.pageSize,
    sort: filters.sort,
    order: filters.order,
  }

  if (keyword !== '') {
    query.keyword = keyword
  }
  if (filters.status !== '') {
    query.status = filters.status
  }

  return query
}
```

```ts
/** 后端统一响应信封；分页端点还会带 total/page/page_size（`contract.PageResponse` 同形）。 */
export interface Envelope {
  code?: number | undefined
  message?: string | undefined
  request_id?: string | undefined
  data?: unknown
  total?: number | undefined
  page?: number | undefined
  page_size?: number | undefined
}

/**
 * 校验信封本身并原样返回：分页端点需要 total/page/page_size，只取 data 会丢掉它们。
 * 调用方仍然只在这里判断 code，不在 feature 里重复错误处理。
 */
export function unwrapEnvelope<T extends Envelope>(body: T | undefined): T {
  assertOk(body)
  return body as T
}
```
把 `unwrap` / `unwrapOk` 里重复的三段校验抽成同一个 `assertOk(body: Envelope | undefined): void`（`unwrap` 之后再检查 `data` 是否为 `undefined`/`null`）。

`src/features/tenants/api.ts`：用 `unwrapEnvelope` 取分页信封、`unwrap` 取 `TenantBodyResponse.data`、`unwrapOk` 处理 `response.Body` 写操作；`listTenants` 返回 `{ items, total, page: envelope.page ?? query.page, pageSize: envelope.page_size ?? query.page_size }`；`listPlans` 固定 `{ page: 1, page_size: 100 }`（后端上限 100）。

```ts
/** plan_id=0 表示未分配；套餐列表命中则用套餐名，否则退回 #id。 */
export function resolvePlanName(planId: number, plans: Plan[]): string {
```

```ts
  defaultOptions: {
    queries: { retry: false, staleTime: 30_000, refetchOnWindowFocus: false },
```

`src/main.ts`：`app.use(VueQueryPlugin, { queryClient })`（放在 `app.use(ElementPlus)` 之后、`app.use(router)` 之前）。

`src/features/tenants/views/TenantsView.vue`（`<script setup lang="ts">`）要点：

- `const canView = computed(() => hasPermission(apiResource('/tenants'), 'GET'))`；`canCreate`、`canManagePlans` 同理。
- `const filters = reactive<TenantFilters>({ page: 1, pageSize: 20, sort: 'id', order: 'desc', keyword: '', status: '' })`。
- `const query = computed(() => buildTenantListQuery(filters))`；`useQuery({ queryKey: ['tenants', query], queryFn: () => listTenants(query.value), enabled: canView })`。
- 状态判定顺序：`!canView` 或错误码 `1003` → `data-test="tenants-forbidden"`（`el-result`，标题「没有访问租户管理的权限」，说明「请让管理员为你的账号分配 /api/v1/tenants 的 GET 权限」，不到登录页）；`isPending` → `data-test="tenants-loading"`；`isError` → `data-test="tenants-error"`（`el-alert` + 「重试」按钮调 `refetch()`，文案带 `requestId`）；`items.length === 0` → `data-test="tenants-empty"`（`el-empty` + 主操作新建）；否则 `data-test="tenants-table"`。
- 筛选区：`data-test="tenant-keyword"`（`el-input` + 搜索按钮，触发时把 `page` 重置为 1）、`data-test="tenant-status"`（`el-select`，选项 `全部('')` / `启用(1)` / `停用(0)`）、排序 `el-select`（`id`/`code`/`created_at`）+ `asc`/`desc`；`el-pagination` 绑 `total`。
- 列：编码、名称、状态（`el-tag` 语义色：`1` → success「启用」，`0` → info「停用」）、套餐（`resolvePlanName(row.plan_id, plans)`）、创建时间、操作。

## 不变量清单（实现时逐条自检）

1. 前端任何请求都不带租户标识（header / query / body 都没有 `tenant_id`、`tenant`、`tid`）。
2. 未筛选状态时 `/tenants` 请求**不含** `status` 参数；`status=0` 保留。
3. `permissions` 是唯一授权依据；`roles` 只用于展示，代码里不出现角色名字符串（E2E 里的 `'超级管理员'` 只作为假数据）。
4. `403`（1003）→ 无权限页；`401` → 刷新/回登录。二者不混用，403 不触发登出。
5. `GET /auth/me` 的 500/网络错误不登出；401/404 清会话回登录。
6. 写操作用 `unwrapOk`，分页用 `unwrapEnvelope`，载荷型端点用 `unwrapPayload`；`unwrap` 只用于「信封 + 必须有 data」的响应。
