# 平台角色管理与权限分配

## 背景

后端 `jimu@5ff2d0506a7a0c87e32b0d12a6cfb64a79d2368a` 补齐系统角色与角色选项契约：

- 角色列表支持 `tenant_id`、`keyword`、`status` 筛选。
- `RoleResponse` 增加稳定 `code`、`scope`、`is_system`；系统角色由后端保护，不能改名、停用或替换权限。
- 新增 `GET /roles/options`，只返回指定租户中启用且可分配的角色，供用户创建和角色替换使用。
- 创建角色支持平台管理员指定 `tenant_id`。
- `PUT /roles/{id}` 通过 `status=0|1` 停用或恢复；`DELETE /roles/{id}` 永久删除未分配给用户的自定义角色，已分配给用户返回 `409`。
- 新增 `GET /roles/{id}/permissions`，权限回显不再依赖角色详情。
- 权限 ID 改为字符串，`permission_ids` 支持空数组清空权限。
- 角色与权限管理端点仅平台管理员可访问。

## 页面范围

`/admin/roles` 首版提供：

- 角色列表：名称、稳定 code、系统/自定义标识、平台/租户范围、所属租户、状态与创建时间。
- 筛选：租户、角色名称、状态。
- 新建角色：必须选择所属租户。
- 编辑角色：名称、说明、状态；租户不可修改。
- 停用角色：通过 `PUT status=0` 二次确认，之后可通过编辑重新启用。
- 删除角色：通过 `DELETE` 二次确认，永久删除未分配给用户的自定义角色；已分配给用户时展示后端 `409` 错误。
- 分配权限：读取当前权限，按资源分组展示全部可分配权限，整体替换保存。
- 系统角色：不提供编辑、停用和删除；具备读取权限时打开只读权限抽屉，不显示保存按钮。

用户、租户和角色页继续共用 `ManagementPage.vue` 的页头、筛选卡片、状态、表格和分页骨架。

## 权限边界

- 导航和页面准入使用 `GET /api/v1/roles`。
- 用户创建与角色替换使用 `GET /api/v1/roles/options`，不要求租户管理员具备角色列表权限。
- 新建、编辑、停用、删除和权限分配分别检查各自请求路径。
- 权限按钮还要求具备 `GET /api/v1/permissions` 与 `GET /api/v1/roles/*/permissions`；保存权限额外要求 `POST /api/v1/roles/*/permissions`。
- 平台管理员范围由后端判定；前端不根据角色名称推断权限。
- 前端按 `is_system` 隐藏系统角色写操作；后端仍执行最终授权。
- 权限目录是全局资源，不携带租户参数。

## 交互

- 新建和编辑使用 480px 右侧抽屉。
- 权限分配使用 560px 右侧抽屉，窄屏占满视口。
- 权限列表支持名称、资源、动作搜索。
- 每个资源分组支持全选；顶部显示已选数量。
- 保存前必须成功读取当前权限和权限目录，避免以空集合误覆盖。
- 清空全部勾选代表移除该角色的全部权限。
- 系统角色的权限抽屉只读，说明权限由后端维护；角色选项中的系统角色带“系统”后缀。

## 测试

- `role-params.spec.ts`：空筛选省略、`status=0`、租户和关键字透传。
- `roles-api.spec.ts`：分页、字符串 ID、创建、更新、停用、权限目录分页、当前权限和整体替换。
- `users-api.spec.ts`：`/roles/options` 指定租户和当前身份两种请求。
- `users-view.spec.ts`：租户管理员仅凭 `/roles/options` 管理用户角色，系统角色在选项中显式标识。
- `roles-view.spec.ts`：共享骨架、筛选、创建、编辑、停用、永久删除、系统角色元数据与只读权限、权限回显与保存、细粒度权限隐藏。
- `e2e/roles.spec.ts`：真实浏览器中的系统角色只读、自定义角色停用/删除、角色页、导航、权限抽屉和保存载荷。
